# Client delivery and dashboard services

The Client app and `mdb service` supervise two current-user services: the outbox watcher and the local client dashboard. Neither needs root, changes system settings, nor puts the bearer token value in service arguments. Store the bearer token in a separate file with mode `0600`.

```sh
chmod 600 ~/.config/engram/client.token
mdb service install --url https://memory.example/mcp --token-file ~/.config/engram/client.token
mdb service status
mdb service logs
mdb service stop
mdb service start
mdb service uninstall
```

`ENGRAM_MCP_URL` and `ENGRAM_TOKEN_FILE` can replace the install flags. Optional `--workspace`, `--project-dir`, and `--outbox` set watcher scope and local queues. `--platform macos|linux` selects a definition explicitly; otherwise the current OS is used. `--dry-run` prints both generated units and the dashboard launcher. An identical install is a no-op. App updates that change bundled Node or `mdb` paths upgrade matching units in place; a missing or stale dashboard unit is installed or replaced without restarting the outbox watcher. Changing the URL, token path, workspace, outbox, or project still requires the Server form or uninstalling first. The client dashboard **Server** form previews URL and token-file changes before applying them; it reconfigures and restarts only the outbox watcher, leaving the client-dashboard unit running. It preserves unrelated `client.env` lines and rolls back earlier targets if a later write fails. Installation refuses root unless `--allow-root` is explicitly passed for an isolated account, and honors `ENGRAM_AUTO_RECONNECT=0`.

The client dashboard binds only to `127.0.0.1` and defaults to port `4872`. `ENGRAM_CLIENT_DASHBOARD_PORT` in `~/.config/engram/client.env` or the service environment overrides the port. `mdb service dashboard-url` returns JSON with the safe URL, whether first-time setup is pending, password state, port, and whether a valid private note was available. It reads only an owned regular note with mode `0600` or `0400`, rejects symlinks and files over 64 KiB, and only accepts a setup token URL on the configured loopback port. If the unit has not started and the note is empty, it returns the plain loopback URL with `noteAvailable:false`. The Client menu's **Open dashboard** opens the setup URL when needed; **Copy first-time sign-in link** appears only during initial setup. An explicit `ENGRAM_DASHBOARD_URL` in `client.env` overrides the URL opened by the Client menu. `mdb service status` reports outbox and dashboard status, including the dashboard port and loopback host.

macOS installs `~/Library/LaunchAgents/dev.engram.outbox-watch.plist` and `dev.engram.client-dashboard.plist`. Linux installs `~/.config/systemd/user/engram-outbox-watch.service` and `engram-client-dashboard.service`. Both restart on failure. The dashboard runs the packaged bundle's own Node and `mdb.js` by absolute path. Its setup URL is written to `~/.config/engram/client-dashboard.txt` with mode `0600` under `umask 077`, overwritten on each start; dashboard stdout never reaches the shared log. Diagnostics go to `~/Library/Logs/Engram/client-dashboard.log` on macOS, with the existing rotation policy. Outbox diagnostics remain in `client-daemon.log` on macOS or the systemd user journal on Linux (`mdb service logs`).

The dashboard's auth state is separate from the content vault. macOS defaults to `~/Library/Application Support/Engram/client-dashboard/`; Linux defaults to `${XDG_CONFIG_HOME:-~/.config}/engram/client-dashboard/`. `MDB_CLIENT_DASHBOARD_STATE_DIR` relocates the state directory and `MDB_DASHBOARD_AUTH_FILE` selects its auth file. On first use, open **Engram Client → Open dashboard** or choose **Copy first-time sign-in link** and paste it into a browser. The link is a one-time setup credential; keep it private. Once setup is complete, the menu opens the plain local dashboard and the browser asks for the dashboard password.

On macOS both the server and client dashboard show the same native startup alert, including the URL and the first-run or sign-in instruction. Set `MDB_DASHBOARD_ALERT=false` to suppress it. For the supervised client the token-bearing URL is shown only by this alert and stored in the private `client-dashboard.txt` note; it is not written to the shared supervisor log. The client status pill reports service, token-file, capture-server reachability, and outbox state; a failed reachability probe is Attention while events remain buffered locally. The probe is an unauthenticated `/version` request with a three-second timeout and a ten-second cache.

For systemd to start at boot before login, an administrator may enable lingering with `loginctl enable-linger USER`; Engram does not run that command. Tests use a temporary HOME and fake launchctl/systemctl commands; they never install real services or write to a developer's home. `plutil -lint` and `systemd-analyze verify` run when available.

The client dashboard Server form takes a capture URL and a token-file path (default hint: `~/.config/engram/client.token`); it never accepts or displays the token value. The token file must be owned by the current user, regular, and mode `0600` or `0400`. Preview validates URL policy and lists the `client.env`, outbox service, `user.json`, configured Claude/Codex MCP entries, and installed remote hook commands that would change. Missing user configuration, MCP entries, hooks, and services remain skipped rather than being created. Apply requires a fresh dashboard-password check, CSRF-protected session, and a digest that still matches the preview. Connections are separate and hold a server dashboard URL plus dashboard credential; they do not configure capture delivery.
