# Engram Client dashboard

`mdb dashboard --client` is a local, loopback-only dashboard for this device. It defaults to port `4872` and runs without a content vault. Its landing screen, **This device**, reports only local capture configuration and local queue state; it is labeled “Local state of this device. This is not a copy of the server’s data.” Use **Refresh** to fetch the latest local values.

On macOS, starting either the server or supervised client dashboard shows the same native startup alert with its first-run URL. The window appears only on first use, when no dashboard password has been set yet; once a password exists no pop-up appears and the private access token is never shown or printed (the dashboard URL is shown without it). Set `MDB_DASHBOARD_ALERT=false` to disable the alert. For the supervised client, the token-bearing URL appears only in that alert and the private `client-dashboard.txt` note; it is never printed to the shared supervisor log. Other platforms do not display a popup, and the private-note client writes no token-bearing banner to stderr.

The client navigation is **This device**, **Server**, **Workspaces**, **Cached projects**, **Connections**, and **Client settings**, in the same order on every client page. Server-only dashboard APIs and screens are unavailable in client mode. **Server** previews and changes the capture server URL and token file path used by this device. It shows a per-target change table, requires both a checked confirmation and the phrase `APPLY SERVER CHANGE`, then asks for the dashboard password again before applying.

The device view shows user-level capture identifiers, hosts, mode, pause/consent and project filters; the capture server host only; remote-spool and outbox counts; the oldest queued write and last recorded delivery event; service status; bounded trusted/bound project paths; token-file presence and mode status; dashboard listener and runtime versions. It never returns the token value, capture URL path, or token file contents. It does not fetch or cache server workspace or memory data.

**Workspaces** combines the credential-authorized workspace list returned by the configured server's `mdb_workspace_list` MCP operation with trusted project bindings, context-cache metadata, queued-write metadata, and replica workspace status on this device. The remote lookup has a 1.5-second timeout; the page returns local state when the server is unreachable and marks the last known server list stale with its age. Results are cached for ten seconds and capped at 200 server rows, 2,000 cache metadata files, 5,000 queued writes, and the existing 200 trusted-folder bound. It reports connection status, modes, cache age/staleness, queued counts/bytes, replica counters, and bound folder names. It never returns cached context, queued bodies, token values, or credentials. Write access is shown only when the server includes it in its workspace-list result; the current MCP operation does not report write access, so the dashboard displays **Unknown**.

In client mode, the status pill reflects the client service, private token-file permissions, server reachability, and queued, conflicting, or rejected events. Its tooltip lists the plain-language checks. “Connecting” appears only before the first successful client status response; a failed status request changes the pill to Problem. The reachability check requests only the configured server origin’s `/version`, without credentials, with a three-second timeout and a ten-second result cache. An unreachable server is Attention because local events remain queued for delivery.

Password and connection state are independent of the content vault. By default, state is stored under `~/Library/Application Support/Engram/client-dashboard/` on macOS and `${XDG_CONFIG_HOME:-~/.config}/engram/client-dashboard/` on Linux. `MDB_CLIENT_DASHBOARD_STATE_DIR` selects another state directory; `MDB_DASHBOARD_AUTH_FILE` selects the auth file. Directories are private (`0700`) and state files are private (`0600`).

`mdb service install|start|stop|status|uninstall` supervises both the outbox watcher and the client dashboard. The dashboard binds to `127.0.0.1`; set `ENGRAM_CLIENT_DASHBOARD_PORT` in `~/.config/engram/client.env` or the service environment to override `4872`. Changing the port requires uninstall and reinstall. Its one-time setup URL is written to `~/.config/engram/client-dashboard.txt` with mode `0600`, under `umask 077`; dashboard diagnostics go to `~/Library/Logs/Engram/client-dashboard.log` and use the existing rotation policy. The setup token is not written to that shared log.

For first-time setup, use **Engram Client → Open dashboard**. It reads the private note and opens the complete one-time URL; **Copy first-time sign-in link** copies that URL when setup is pending. If the dashboard has not started yet, Open dashboard uses the plain local URL and the note is refreshed on the next poll. After a password is set, the setup link is hidden and Open dashboard uses the plain URL. `mdb service dashboard-url` exposes the same state as JSON for app integrations; it rejects missing, unsafe, malformed, or oversized notes and never returns the token outside the `url` field.

After a Client app update, `mdb service install` reconciles executable and bundle paths automatically when the saved URL, token-file path, workspace, outbox, and project settings still match. It can add a missing dashboard unit or replace a stale dashboard unit without restarting the outbox watcher. To change those saved settings, use the Server form or uninstall before installing with new values.

The Server form accepts only HTTPS, loopback HTTP, or an explicitly trusted tailnet URL, with no embedded credentials, query, or fragment. The token is never entered into the form: provide a path to an owned regular file with mode `0600` or `0400`. Preview binds a digest to the normalized URL, token-file path, and current configuration files; apply refuses a stale preview. Updates preserve unrelated `client.env` entries and comments, use atomic file replacement, and roll back changed targets when a later update fails. Targets that are absent, including MCP entries and hooks, are shown as skipped and are never created. The audit records target names and the URL host only.

**Connections** administers a remote server dashboard. Its Dashboard server URL and dashboard credential are separate from the capture server URL and token file configured by **Server**. Credentials remain in private local files and are never returned to the browser. See [client-daemon.md](client-daemon.md) for service lifecycle details.


## Replica sync and cached projects

The **Cached projects** tab always starts with **Project folders on this device**, a table of every trusted project binding recorded on this machine, including local, remote and replica modes. It remains visible when replica sync is disabled and reports unavailable mount paths as **unmounted**. Remote folders include only SessionStart cache age and stale status, plus queued outbox counts and bytes; cache text, queued write bodies and credentials are never returned. The table is bounded to 200 folders and status work is approximate when the local scan exceeds its short time budget. Full paths are available on hover. With no bindings, the tab explains how to run `mdb init --project` or enable replica sync.

The session-only `GET /api/client/folders` response is `{rows, approximate}`. Each row contains `folderName`, `path`, `workspaceId`, `mode`, `trusted`, `mounted`, `domains`, `hooksInstalled`, `contextCache: {ageMs, stale}`, `queuedWrites`, `queuedBytes`, and `replica: {state, pending, conflicts}`. Results are cached locally for ten seconds.

Below that table, the tab reports each initialized replica and enrolled workspace. The replica status distinguishes **Sync mode**, **Syncing**, **Cache mode (offline)**, **Conflict**, **Access refused**, **Paused**, **Epoch changed**, and **Daemon stopped**. A daemon status older than three 30-second intervals is considered stopped, so stale status cannot appear green. The tab shows queue counts, last pull/push, daemon process details and redacted last error.

Use **Enable replica sync** after configuring the server URL and private token-file path in Client settings. The dashboard reads those saved settings and never asks for or displays the token. Add workspaces by ID, sync them on demand, and resolve conflicts by choosing the server version, the local candidate, or edited text. Conflict versions are rendered as plain text. Removing a workspace unenrolls it and keeps the local data; purge remains a CLI-only operation.

Personal memory, wiki, shared knowledge, discoveries and unrelated workspace data remain live remote requests and are never cached.

## Replica sync and cached projects

The client dashboard header reports replica health, the overall last sync (relative and absolute), and a detail panel for server contact, pull/push, profile snapshot, queues, daemon uptime, retry timing, and redacted errors. A missing daemon, missing status file, or status older than three daemon intervals is shown as **Daemon stopped**. The **Cached projects** tab lists enrolled workspaces, trusted project-folder bindings, replica counters, and an approximate on-disk byte count. Size measurement scans only that replica workspace and immutable revision files attributed to it by the local commit journal; it stops after 20,000 files or 250 ms and marks capped results approximate. Results are cached for 60 seconds.

Conflict versions are presented as plain text. The dashboard limits each returned conflict body to 100 KB and indicates when text was truncated; it never interprets Markdown or HTML. Take server, take mine, edited text, and discard actions use the replica conflict APIs and preserve immutable candidate revisions. Personal, wiki, and shared data remain live server data and are never cached. **Enable replica sync** uses the URL and private token file already saved in Client settings and installs the per-user daemon service; token contents are never displayed.
