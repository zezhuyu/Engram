## Implemented and tested (deterministic provider; docs/user-insight.md)
- **Source classes** computed from the cited objects (`explicit`, `user_conversation`, `wiki_exposure`, `agent_observation`, `dream`), shown to the model as `source_class` and recomputed by the rules; the model's own class/confidence claims are overridden or rejected.
- **C1** an explicit correction supersedes an inferred preference, linking the user's words; the superseded revision stays readable; projection regenerated. **C2** wiki/imported material only yields an `interest` marked exposure; preference/goal/capability claims from it are rejected. **C3** agent conclusions cannot override user statements (rejected); agent-only claims stay `hypothesis` and need `--confirm-hypothesis`. **C4** workspace and global insights with the same key coexist (applicability via `scopeLabel`). **C5** sensitive candidates need confirmation, are counted but never listed in projections or any index, and are readable only with a profile grant. **C6** repeated extraction is one proposal; a same-claim/different-evidence attempt is rejected as redundant; projections are byte-stable and keep authored text. **C7** spans must be verbatim in a real, readable source; fabricated quotes, missing spans, dream evidence, unreadable evidence and speaker mis-attribution are rejected.
- Passive-capture path: user-authored events enqueue one incremental profile job per scope; sources are taken in priority order with a cursor (no reprocessing).
- Agents have no MCP tool to state or correct a user fact; corrections are CLI/SDK (`mdb profile correct`).

## Defects found and fixed while building M2
- Workspace-applicable insights would have been stored inside the workspace, readable by every agent with workspace access. Insights are now stored in the user-private profile area; workspace relevance is a label.
- The critic's keyword sensitivity flag did not update the stored `sensitivity`, which would have listed a flagged item in the projection. The flag is now authoritative at commit.
- The intelligence engine still loaded the whole corpus per evidence reference, per critic pass and per job (`listDocuments()`); all replaced by manifest-based targeted loads (insights, wiki, retrospectives all go through these paths).
- Legacy profile tests used non-user "evidence" and unquoted claims; updated to the real evidence model (their guarantees are unchanged and also covered by the new suite).

## Not done / not verified
- No real-model extraction evaluation; false-positive rate and provenance coverage on real model output are **unmeasured**.
- Free-text corrections are recognized only if the model sets `explicitStatement`; there is no rule-based detector.
- Sensitivity detection is a keyword heuristic.
- Confidence labels are coarse and derived from source counts only.
