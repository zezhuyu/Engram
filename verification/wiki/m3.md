## Implemented and tested (docs/wiki-and-memory-jobs.md)
- **Incremental compile:** a new source supplies itself plus at most three affected pages (found through `derived_from` dependency edges in the manifest, then keyword overlap). Tests: only the related page of a vault with 20+ unrelated pages is supplied (bounded context); the related page gets a **new revision** (old revision, evidence and dependency edges preserved, new edges added); an unrelated page gets none; a source with no related page creates a new page; dependency edges find an affected page that shares no keywords with the source.
- **Deterministic safety rules:** engine-derived `derived_from` edges; model may target only a page it was shown; at least one real source must be cited; evidence objects and revisions must exist; every statement paragraph or list item carries `[n]` or `(inference)` (open questions exempt); stale-page proposals are rejected and the human edit survives; repeated events are the same proposal; private workspace sources compile only inside their workspace; sources are byte-identical after compilation.
- **Bounded repair:** on a citation failure the model is told the exact problem once; compliant output is accepted, non-compliant output is rejected, and there is no loop.
- **Retrospective + handoff at session end** (also for abandoned sessions, labeled INCOMPLETE with the outcome stated as unknown), both in the owner's queue, citing evidence with user, assistant and tool statements kept distinct; retrievable on demand; nothing promoted to global scope. `mdb memory record` saves notes, decisions, findings and task completion through the same registration and redaction.

## Real model (opt-in, `MDB_REAL_MODEL_TEST=1 MDB_TEST_PROVIDER=claude-cli node --test dist/tests/wiki/real-model.test.js`)
Real Claude via the CLI agent: first run, the page was **refused by the citation lint** (an uncited list of open questions) — the gate worked and nothing was committed. After tightening the lint (list items judged individually, questions exempt) and adding the one-shot repair, a repeat run produced a compliant first page and a second source that **updated the existing page in place** (revision 2). One run each; model quality (groundedness, hallucination rate) was not scored.

## Not done / not verified
- No claim-to-span support check (a cited span supporting the sentence is not machine-verified).
- No page merge/split; a source updates at most one page or creates one.
- Re-importing a changed file is a new source with no explicit "supersedes" edge.
- No host emits a task-complete hook; `task.completed` is explicit only.
- Affected-page selection is lexical/graph based, not semantic.
